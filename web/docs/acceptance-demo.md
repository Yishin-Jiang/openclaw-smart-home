# 第九階段展示與驗收腳本

## 展示前檢查

1. 確認 VM 防火牆已只對 LAN 放行 TCP 8443，並在展示裝置信任 `deploy/caddy-local-root.crt`。
2. 開啟 `https://<SMART_HOME_HOST>:8443`，以部署帳號登入。
3. 確認控制中心顯示 OpenClaw 與 Home Assistant 已連線。
4. 確認設備卡只顯示 HA 實際存在的設備，攝影機卡不會自動載入畫面。
5. 開啟能耗分析，確認數值來源顯示 P110M 的 HA Entity ID；缺少歷史基準的欄位必須顯示 `—`。

## 固定展示流程

依序送出下列要求，每次等待處理流程完成後再進行下一項：

1. `查詢目前有哪些設備在線上？`
   - 預期：只讀查詢，流程顯示取得 Home Assistant 即時狀態。
2. `關閉客廳的燈`
   - 預期：依序顯示操作前查詢、控制工具、操作後驗證與回覆；驗證失敗時不得回報完成。
3. `攝影機目前有連線嗎？不要取得快照`
   - 預期：只回覆連線狀態，網站不顯示照片。
4. `取得並顯示客廳攝影機的最新快照`
   - 預期：使用者明確要求後才拍攝，照片使用短效網址並會過期。
5. 使用麥克風說出 `打開客廳的燈`
   - 預期：先顯示可編輯的辨識文字；按下「確認並送出」後才執行。

## 自動唯讀回歸測試

在 VM 的網站目錄執行 `npm run smoke`。測試涵蓋控制中心、能耗頁、Gateway 健康狀態、HA 狀態、HA 分區與能耗資料契約，不會控制任何設備。

## 主動感知驗收

1. 讀取 `GET /api/monitor/status`，確認 `enabled`、`configured` 為 `true`，三個監測實體均存在且 `lastError` 為 `null`。
2. 測試通知必須明確標示為測試；確認 LINE 收到提醒，內容包含唯讀確認與「系統沒有控制任何設備」。
3. 專用 `home-monitor` Agent 的工具白名單只能包含 `homeassistant__GetLiveContext` 與 `message`；不得包含 HA 控制或攝影機工具。
4. 人工離線驗收時，燈與 P110M 未滿 2 分鐘、攝影機未滿 5 分鐘不得通知；達門檻後只提醒，不自動採取動作或取得快照。
5. 設備恢復後需連續正常 1 分鐘才通知恢復；同一離線事件最多提醒 2 次，兩次至少間隔 30 分鐘。
6. P110M 開啟滿 4 小時只顯示「持續使用中」，不得宣稱故障、危險或忘記關閉。

## 輕量記憶驗收

1. 傳送「記住我晚上偏好暖色燈」，確認網站只出現待確認卡片；尚未按下確認前，`GET /api/preferences` 必須顯示 `pending`。
2. 按下「確認記住」後，偏好變為 `active`，且 `USER.md` 只更新受管理區塊並保留原內容。
3. 建立新對話後詢問晚間燈光偏好，OpenClaw 可以引用已確認內容，但不得因此自動操作燈具。
4. 在 `/memory` 修改、停用及刪除偏好，確認畫面、`preferences.json` 與 `USER.md` 同步。
5. 嘗試儲存密碼、Token、RTSP 網址或「現在誰在家」等內容，API 必須拒絕。
6. 完成一次查詢與一次控制要求後，使用紀錄需顯示類型、結果、Entity ID 與耗時；不可包含模型思考、Token 或快照。
7. 單筆刪除及清除全部紀錄後，偏好資料不得受影響。
