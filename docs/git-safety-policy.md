# Git 安全與可重現部署政策

更新日期：2026-09-15

## 目的

此專案使用 Git 保存可重現部署所需的原始碼、公開範例與操作文件，同時避免把憑證、個人記憶、攝影機畫面及執行期資料送到遠端儲存庫。

## 可納入版本控管

- `web/` 的應用程式原始碼、測試、部署範例與 lockfile。
- `contracts/`、`design/` 與 `docs/` 中經人工檢查的規格、設計與文件。
- `.env.example` 等只含假值或欄位名稱的設定範例。
- 已完成安全檢查的 `skills/ha-camera-snapshot/` 原始碼；不得包含 Token、影像、快取或 ffmpeg 執行檔。
- 必要的 workspace 操作規範，但送出前仍須人工檢查是否含個人資料或區網資訊。

## 永不納入版本控管

- `.env`、Token、密碼、私鑰、用戶端憑證與真實 Cookie。
- 攝影機快照、錄影、音訊，以及由畫面推論出的居住或身分資訊。
- `MEMORY.md`、`memory/`、執行期狀態、資料庫、log、cache、建置輸出與套件目錄。
- 臨時測試資料、PDF 轉圖、壓縮封存檔及本機下載的二進位工具。
- VM 中正在使用的真實 `USER.md`、憑證檔或智慧家庭偏好資料；不可直接同步回公開儲存庫。
- 含實際 VM 使用者、LAN 拓撲或即時觀測值的基礎設施稽核；應保留在本機或先完成去識別化。

## G350 特別規則

- G350 的 `idle` 是 Home Assistant 實體 metadata，不能單獨證明實體攝影機在線。
- 網站顯示的在線／離線狀態應沿用 G350 專用的串流探測流程。
- metadata 查詢不得順便抓取畫面；只有明確要求取得、顯示或分析當下快照時，才授權單次擷取。
- 任何測試快照均留在本機並受 `.gitignore` 保護。

## 安全提交流程

1. 先執行 `git status --short --ignored`，確認臨時檔與敏感資料為 ignored。
2. 不使用 `git add .`；依照審查過的清單逐一加入明確路徑。
3. 檢查 `git diff --cached --stat` 與 `git diff --cached`。
4. 再做一次秘密字串掃描與必要的建置／測試。
5. commit 前確認沒有攝影機媒體、VM 執行期資料或使用者個資。
6. `git push` 永遠由使用者本人執行；Codex 不自行推送。

## 權責

- Codex 可以整理檔案、補上忽略規則、檢查差異並提供建議的 stage 清單。
- 除非使用者另有明確要求，Codex 不執行 stage 或 commit。
- 所有遠端 Git 推送均由使用者本人負責。
